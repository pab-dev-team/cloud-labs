# Книга рецептов

Сервис для нулевой лабораторной по DevOps. Показывает готовые рецепты и позволяет
добавлять свои: название, ингредиенты и шаги приготовления. Все рецепты хранятся
в отдельном сервере MySQL и остаются после перезагрузки страницы и перезапуска Flask.
Коллекция общая для всех посетителей; регистрации, поиска и редактирования пока нет.

Стек: Python, Flask, MySQL Connector/Python, HTML, CSS и обычный JavaScript.
Фронтенд обращается к Flask через JSON API. Для этой лабы Flask также отдаёт
файлы фронтенда; в следующих лабах их сможет отдавать отдельный nginx.

## Требования

- Python 3.13 или новее.
- MySQL 8.4 или новее, работающая как отдельный сервер.
- Для установки MySQL на macOS используется Homebrew.

## 1. Запустить MySQL

Если MySQL ещё не установлена:

```sh
brew install mysql
```

Запустите сервер и откройте консоль администратора:

```sh
brew services start mysql
mysql -u root -p
```

У свежей установки Homebrew пароль root может быть пустым: нажмите Enter.
Создайте новую базу и отдельного пользователя. Замените `your-strong-password`
своим паролем; такой же пароль понадобится в `.env`:

```sql
CREATE DATABASE recipes CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'recipes_app'@'localhost' IDENTIFIED BY 'your-strong-password';
GRANT SELECT, INSERT, CREATE ON recipes.* TO 'recipes_app'@'localhost';
EXIT;
```

Не выполняйте создание повторно, если база и пользователь уже подготовлены.
Приложение использует обычного пользователя, а не root. Право CREATE нужно
для начальной подготовки таблицы.

## 2. Установить зависимости

Из корня проекта:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
```

## 3. Настроить подключение

Если `.env` ещё нет, скопируйте пример:

```sh
cp .env.example .env
chmod 600 .env
```

Откройте `.env` и замените `MYSQL_PASSWORD` паролем созданного пользователя.
При необходимости измените адрес, порт или имя базы. Если пароль содержит
специальные символы оболочки, заключите значение в одинарные кавычки.
`.env` исключён из Git; реальные пароли не нужно коммитить.

Загрузите настройки в окружение текущего терминала:

```sh
set -a
source .env
set +a
```

Файл `.env` не загружается приложением автоматически. В новом терминале
повторите активацию `.venv` и загрузку окружения.

## 4. Создать таблицу и загрузить начальные рецепты

```sh
flask --app backend.app init-db
```

Команда создаёт таблицу `recipes` и добавляет три рецепта, если таблица пустая:
овсяную кашу с яблоком, омлет с помидорами и пасту с томатным соусом.
Повторный запуск не дублирует данные и не удаляет пользовательские рецепты.

В таблице четыре поля: `id`, `title`, `ingredients`, `instructions`.
Название ограничено 255 символами, ингредиенты и шаги — 10 000 символами каждый.

## 5. Запустить приложение

```sh
flask --app backend.app run --host 127.0.0.1 --port 5000
```

Откройте [http://127.0.0.1:5000](http://127.0.0.1:5000).
Если порт 5000 занят, укажите, например, `--port 8000` и откройте соответствующий адрес.
Flask запускается без отладчика. Для остановки нажмите Ctrl+C.

## Проверка для отчёта

1. Откройте страницу: начальные рецепты должны отображаться.
2. Заполните название, ингредиенты и шаги, нажмите «Сохранить рецепт».
3. Перезагрузите страницу: новый рецепт остаётся в списке.
4. Остановите Flask и запустите снова: рецепт по-прежнему на месте.
5. Проверьте запись непосредственно в MySQL:

```sh
mysql -h 127.0.0.1 -u recipes_app -p recipes
```

```sql
SELECT id, title FROM recipes ORDER BY id DESC;
```

Для отчёта приложите ссылку на репозиторий, этот README и скриншот страницы
с добавленным рецептом. Пример интерфейса: [скриншот](docs/screenshot.jpg).

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/recipes` | JSON-массив рецептов, новые первыми |
| `POST /api/recipes` | Сохраняет рецепт, возвращает его с `id` и статусом 201 |

Пример добавления:

```sh
curl -i http://127.0.0.1:5000/api/recipes \
  -H 'Content-Type: application/json' \
  -d '{"title":"Чай","ingredients":"Вода — 250 мл\nЧай — 1 ч. л.","instructions":"Заварить чай горячей водой."}'
```

Поля обязательны. Пустые строки, неверные типы и превышение длины возвращают
400; запрос без JSON — 415; слишком большой запрос — 413; ошибка MySQL — 503.
SQL-запросы используют параметры, а фронтенд выводит пользовательский текст
через `textContent`, чтобы содержимое рецептов не исполнялось как HTML.

## Тесты

Базовые проверки без подключения к БД:

```sh
python -m unittest discover -s tests -v
```

Для проверки с настоящей MySQL создайте отдельную тестовую базу через root:

```sql
CREATE DATABASE recipes_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
GRANT SELECT, INSERT, DELETE, CREATE ON recipes_test.* TO 'recipes_app'@'localhost';
```

После загрузки `.env` запустите:

```sh
MYSQL_TEST_DATABASE=recipes_test python -m unittest discover -s tests -v
```

Тест проверяет повторную начальную загрузку и сохранение рецепта через API,
затем читает его через новое соединение. Удаляет только запись, которую сам
создал. Имя тестовой базы должно заканчиваться на `_test`.
