# Книга рецептов

Сервис для нулевой лабораторной по DevOps. Показывает готовые рецепты и позволяет
добавлять, редактировать и удалять свои: название, ингредиенты и шаги приготовления. Все рецепты хранятся
в отдельном сервере MySQL и остаются после перезагрузки страницы и перезапуска Flask.
Коллекция общая для всех посетителей; регистрации и поиска пока нет.
Рецепты, добавленные через форму, может редактировать и удалять любой посетитель.
Начальные рецепты защищены от изменения и удаления на стороне API.

Стек: Python, Flask, MySQL Connector/Python, HTML, CSS и обычный JavaScript.
Фронтенд обращается к Flask через JSON API. Для этой лабы Flask также отдаёт
файлы фронтенда; в следующих лабах их сможет отдавать отдельный nginx.

## Требования

- Python 3.13 или новее.
- MySQL 8.4 или новее, работающая как отдельный сервер.
- Для установки MySQL на macOS используется Homebrew.

## 1. Запустить MySQL

Если MySQL ещё не установлена:

```sh
brew install mysql
```

Запустите сервер и откройте консоль администратора:

```sh
brew services start mysql
mysql -u root -p
```

У свежей установки Homebrew пароль root может быть пустым: нажмите Enter.
Создайте новую базу и отдельного пользователя. Замените `your-strong-password`
своим паролем; такой же пароль понадобится в `.env`:

```sql
CREATE DATABASE recipes CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'recipes_app'@'localhost' IDENTIFIED BY 'your-strong-password';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE ON recipes.recipes TO 'recipes_app'@'localhost';
EXIT;
```

Не выполняйте создание повторно, если база и пользователь уже подготовлены.
Приложение использует обычного пользователя, а не root. Права ограничены таблицей
`recipes`; право CREATE нужно для её начальной подготовки.

## 2. Установить зависимости

Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
```

В Fish активируйте окружение командой `source .venv/bin/activate.fish`.
В bash или zsh команда — `source .venv/bin/activate`.

## 3. Настроить подключение

Если `.env` ещё нет, скопируйте пример:

```sh
cp .env.example .env
chmod 600 .env
```

Откройте `.env` и замените `MYSQL_PASSWORD` паролем созданного пользователя.
При необходимости измените адрес, порт или имя базы. Если пароль содержит
специальные символы, заключите значение в одинарные кавычки.
`.env` исключён из Git; реальные пароли не нужно коммитить.

Flask CLI загружает `.env` автоматически благодаря `python-dotenv`.
Пароль не нужно вручную задавать в оболочке. Поэтому после настройки достаточно
выполнять показанные ниже команды `flask` из каталога проекта.

## 4. Создать таблицу и загрузить начальные рецепты

```sh
.venv/bin/flask --app backend.app init-db
```

Команда создаёт таблицу `recipes` и добавляет три рецепта, если таблица пустая:
овсяную кашу с яблоком, омлет с помидорами и пасту с томатным соусом.
Повторный запуск не дублирует данные и не удаляет пользовательские рецепты.

В таблице пять полей: `id`, `title`, `ingredients`, `instructions`, `is_builtin`.
Признак `is_builtin` отличает начальные рецепты от пользовательских.
Название ограничено 255 символами, ингредиенты и шаги — 10 000 символами каждый.

### Обновление существующей установки

Если таблица была создана до появления редактирования, выполните в консоли root:

```sql
ALTER TABLE recipes.recipes ADD COLUMN is_builtin BOOLEAN NOT NULL DEFAULT FALSE;
GRANT UPDATE, DELETE ON recipes.recipes TO 'recipes_app'@'localhost';
```

`ALTER TABLE` требуется только при отсутствии столбца `is_builtin`.
Затем выполните `.venv/bin/flask --app backend.app init-db` и перезапустите Flask.
Команда помечает исходные рецепты по их первоначальным ID и содержимому.
Остальные существующие записи остаются пользовательскими, их текст не изменяется.

## 5. Запустить приложение

```sh
.venv/bin/flask --app backend.app run --host 127.0.0.1 --port 5000
```

Откройте [http://127.0.0.1:5000](http://127.0.0.1:5000).
Если порт 5000 занят, укажите, например, `--port 8000` и откройте соответствующий адрес.
Flask запускается без отладчика. Для остановки нажмите Ctrl+C.

## Проверка для отчёта

1. Откройте страницу: начальные рецепты должны отображаться.
2. Заполните название, ингредиенты и шаги, нажмите «Сохранить рецепт».
3. Перезагрузите страницу: новый рецепт остаётся в списке.
4. Остановите Flask и запустите снова: рецепт по-прежнему на месте.
5. У добавленного рецепта нажмите «Редактировать», измените поля и сохраните.
   Перезагрузите страницу: изменения должны сохраниться. Кнопка отмены возвращает форму добавления.
6. Нажмите «Удалить» и подтвердите действие. Рецепт исчезает и не возвращается после перезагрузки.
   Удаление нельзя отменить; кнопок редактирования и удаления у начальных рецептов нет.
7. Проверьте запись непосредственно в MySQL:

```sh
mysql -h 127.0.0.1 -u recipes_app -p recipes
```

```sql
SELECT id, title FROM recipes ORDER BY id DESC;
```

Для отчёта приложите ссылку на репозиторий, этот README и скриншот страницы
с добавленным рецептом. Пример интерфейса: [скриншот](docs/screenshot.jpg).

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/recipes` | JSON-массив рецептов, новые первыми |
| `POST /api/recipes` | Сохраняет рецепт, возвращает его с `id` и статусом 201 |
| `PUT /api/recipes/<id>` | Заменяет поля пользовательского рецепта и возвращает обновлённую запись |
| `DELETE /api/recipes/<id>` | Удаляет пользовательский рецепт, возвращает `{"deleted": id}` |

Редактирование принимает те же три поля, что и добавление. Признак начального
рецепта задаёт сервер; передать его через API нельзя. Изменение или удаление
начального рецепта возвращает 403, несуществующего — 404.

Пример добавления:

```sh
curl -i http://127.0.0.1:5000/api/recipes \
  -H 'Content-Type: application/json' \
  -d '{"title":"Чай","ingredients":"Вода — 250 мл\nЧай — 1 ч. л.","instructions":"Заварить чай горячей водой."}'
```

Поля обязательны. Пустые строки, неверные типы и превышение длины возвращают
400; запрос без JSON — 415; слишком большой запрос — 413; ошибка MySQL — 503.
SQL-запросы используют параметры, а фронтенд выводит пользовательский текст
через `textContent`, чтобы содержимое рецептов не исполнялось как HTML.

## Тесты

Базовые проверки без подключения к БД:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Для проверки с настоящей MySQL создайте отдельную тестовую базу через root:

```sql
CREATE DATABASE recipes_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE ON recipes_test.recipes TO 'recipes_app'@'localhost';
```

Запустите тесты командой `env`, которая работает и в Fish:

```sh
env MYSQL_TEST_DATABASE=recipes_test .venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют начальную загрузку, добавление, редактирование и удаление рецепта,
сохранение через новое соединение и защиту начальных рецептов. Удаляют только
записи, которые сами создали. Имя тестовой базы должно заканчиваться на `_test`.
