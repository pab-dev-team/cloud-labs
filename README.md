# Книга рецептов

Позволяет добавлять, редактировать и удалять рецепты: название, ингредиенты и шаги приготовления. Все рецепты хранятся в отдельном сервере MySQL и остаются после перезагрузки страницы и перезапуска Flask.
Коллекция общая для всех посетителей; регистрации и поиска пока нет.
Рецепты, добавленные через форму, может редактировать и удалять любой посетитель.
При первой установке список пустой; рецепты добавляются через форму.

Стек: Python, Flask, MySQL Connector/Python, HTML, CSS и обычный JavaScript.
Фронтенд обращается к Flask через JSON API. Для этой лабы Flask также отдаёт
файлы фронтенда.

## Запуск через Docker

Установите и запустите [Docker Desktop](https://docs.docker.com/desktop/).
На Linux подойдёт Docker Engine с плагином Docker Compose.
Отдельно устанавливать Python и MySQL, создавать виртуальное окружение
или вводить SQL-команды не нужно.

Из корня проекта выполните:

```sh
docker compose up --build -d --wait
```

Команда одинакова в macOS, Linux и Windows PowerShell. Первый запуск может
занять несколько минут: Docker скачивает образы и устанавливает зависимости.
После завершения откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).

Compose запускает два контейнера: `web` с Flask и `db` с MySQL 8.4.
MySQL автоматически создаёт базу и отдельного пользователя приложения.
Flask ждёт готовности базы и выполняет `init-db`, который создаёт таблицу
`recipes` без начальных данных. При первом запуске список рецептов пустой.

В новой таблице четыре поля: `id`, `title`, `ingredients`, `instructions`.
Название ограничено 255 символами, ингредиенты и шаги — 10 000 символами каждый.

## Остановка и повторный запуск

Остановить контейнеры:

```sh
docker compose down
```

Запустить снова:

```sh
docker compose up -d --wait
```

После изменения кода пересоберите приложение:

```sh
docker compose up --build -d --wait
```

Рецепты хранятся в Docker volume `mysql-data` и сохраняются после остановки
и пересборки. Это отдельная база: данные из ранее установленной локальной
MySQL автоматически в неё не переносятся.

Команда `docker compose down -v` удаляет volume вместе со всеми рецептами.
Используйте её только если намеренно хотите очистить базу.

## Необязательные настройки

Проект запускается без файла `.env`. В Compose задан пароль приложения
для локальной разработки; пароль root генерируется автоматически.
Сайт доступен только на этом компьютере, порт MySQL наружу не открывается.
Для размещения на сервере нужно отдельно настроить пароли и доступ.

Если хотите изменить порт сайта или параметры базы, создайте `.env`
из `.env.example`, если этого файла ещё нет.

macOS/Linux:

```sh
cp .env.example .env
chmod 600 .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

Например, установите `APP_PORT=8001`, если порт 8000 занят, и откройте
[http://127.0.0.1:8001](http://127.0.0.1:8001). Остановите предыдущий запуск
через `docker compose down`, затем повторите команду запуска.

Параметры `MYSQL_DATABASE`, `MYSQL_USER` и `MYSQL_PASSWORD` применяются MySQL
при создании новой базы. Изменение `.env` не меняет учётные данные уже
существующей базы. `.env` исключён из Git и Docker-образа.
Адрес `db` и порт 3306 для связи контейнеров задаёт Compose автоматически.

## Проверка и диагностика

Добавьте рецепт через форму, перезагрузите страницу, затем остановите
контейнеры через `docker compose down` и запустите снова. Рецепт должен
остаться в списке. Проверьте его редактирование и удаление.

Состояние контейнеров и журналы:

```sh
docker compose ps
docker compose logs -f
```

Если команда `docker compose` не найдена или Docker сообщает, что не может
подключиться к движку, проверьте установку и запуск Docker Desktop.
На macOS команда `brew install docker` устанавливает только клиент;
для запуска контейнеров нужен работающий движок Docker.

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/recipes` | JSON-массив рецептов, новые первыми |
| `POST /api/recipes` | Сохраняет рецепт, возвращает его с `id` и статусом 201 |
| `PUT /api/recipes/<id>` | Заменяет поля пользовательского рецепта и возвращает обновлённую запись |
| `DELETE /api/recipes/<id>` | Удаляет пользовательский рецепт, возвращает `{"deleted": id}` |

Редактирование принимает те же три поля, что и добавление.
Изменение или удаление несуществующего рецепта возвращает 404.

Пример добавления из терминала macOS/Linux:

```sh
curl -i http://127.0.0.1:8000/api/recipes \
  -H 'Content-Type: application/json' \
  -d '{"title":"Чай","ingredients":"Вода — 250 мл\nЧай — 1 ч. л.","instructions":"Заварить чай горячей водой."}'
```

Поля обязательны. Пустые строки, неверные типы и превышение длины возвращают
400; запрос без JSON — 415; слишком большой запрос — 413; ошибка MySQL — 503.
SQL-запросы используют параметры, а фронтенд выводит пользовательский текст
через `textContent`, чтобы содержимое рецептов не исполнялось как HTML.
